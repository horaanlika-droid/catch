# CATCH 22 — веб-клиент + админ-бот

Полноценное iOS-стиль приложение бара **CATCH 22** (listening bar & bistro, наб. Фонтанки 86)
и Telegram-бот с админ-панелью, через который команда обновляет **всё**: часы работы,
позиции меню и цены, стоп-лист позиций, афишу, бранч, мерч, контакты, соцсети, галерею.
Изменения из бота прилетают в приложение **мгновенно** (SSE), а загруженные фото
обрабатываются сразу — бот скачивает оригинал, кладёт его на сервер и тут же
прописывает в выбранный блок. Никаких пересылок «file_id».

- **Оплата мерча отключена** — гость оставляет заявку, бару в бота прилетает уведомление.
- **Стоп-лист гостей** — в админ-панели; гость из стоп-листа не может оставить заявку через бота.
- **GitHub Pages** показывает приложение, а не README (воркфлоу `.github/workflows/pages.yml`).
- Zero dependencies: чистый Node.js, ставится на [bothost.ru](https://bothost.ru) без сборки.

## Деплой на bothost.ru — только две переменные

1. New project → import из этого GitHub-репозитория (ветка `main`), тип — Node.js.
2. В переменных окружения указать **только**:
   ```
   BOT_TOKEN=123456:AA...
   ADMIN_IDS=111111111,222222222
   ```
3. В настройках проекта включить **«Использовать домен»** и указать внутренний порт
   `3000` (или выставить env `PORT`, равный порту в панели).
4. Deploy. Всё остальное приложение делает само:
   - слушает `0.0.0.0:$PORT`, раздаёт веб-приложение с корня;
   - домен bothost (`DOMAIN` / `BOT_ID`+`USER_ID` → `https://bot-<id>-<uid>-user.bothost.tech`)
     подхватывается автоматически, сам ставит **webhook** `/webhook/<секрет>`;
     если домен ещё не готов — откатывается на **long polling**;
   - данные хранит в `/app/data` (bothost сохраняет папку между деплоями: `state.json`,
     `private.json` — заявки и стоп-лист, `media/` — фото);
   - при первом `getMe` проставляет юзернейм бота в приложение, ставит команды и
     кнопку-меню «📱 Открыть приложение» (web app = тот же домен).

Обновлять контент можно и после пересборки: папка `data/` в git игнорируется.

## Локальный запуск

```bash
node index.js                 # web: http://localhost:3000 (демо без токена)
BOT_TOKEN=… ADMIN_IDS=… node index.js   # полная версия (polling локально)
npm test                      # оффлайн-прогон админ-панели (мок Telegram)
npm run export                # пересобрать public/data.json (снапшот для Pages)
```

Нужен **Node ≥ 18**. Зависимостей нет вообще — `npm install` не обязателен.

## GitHub Pages (для тех, у кого нет Telegram)

1. Settings → Pages → **Source: GitHub Actions** (дальше ничего не надо — workflow сам
   сгенерирует `public/data.json` из сид-данных и задеплоит `public/`).
2. На Pages приложение работает со **снапшотом** seed-данных (статика). Чтобы там были
   **живые данные и загруженные ботом фото**, пропишите адрес с bothost в
   `public/config.js`:
   ```js
   window.CATCH_CONFIG = { apiBase: 'https://bot-xxxx-yyyy-user.bothost.tech' };
   ```
   (workflow перезадеплоит Pages автоматически при пуше в `main`.)

## Что умеет админ-панель бота

`/panel` — главное меню. Блоки:

| Блок | Что меняется |
|---|---|
| 🏷 О заведении | название, подпись, слоган, описание, фото главной, награды/фишки |
| 🕐 Часы работы | строки «дни · время», статус «закрыто», порядок |
| 🍽 Меню | категории → разделы → позиции: название, цена, описание, теги (new/must try/chef), фото, порядок, удаление |
| ⛔ в стоп-лист | снимает позицию с продажи — в приложении она зачёркивается + плашка «Сегодня не продаём» |
| 📅 Афиша | события: дата/время/название/подзаголовок/постер |
| 🥂 Бранч | заголовок, текст, постер, вкл/выкл |
| 🧢 Мерч | карточки-заглушки (цена «скоро»), плашка, заявки без оплаты |
| 🖼 Галерея | фото + подпись (caption) |
| 📞 Контакты | адрес, карты, телефон, почта, ссылка брони + текст про подтверждение |
| 💼 Работа | заголовок, текст анкеты, позиции, вкл/выкл |
| 🧾 Заявки | все заявки с сайта/от гостей: статусы, удаление, «в стоп-лист» тапом |
| ⛔ Стоп-лист | внесение @ник / ID / пересланным сообщением, причина, удаление |
| 📊 Статус | режим (webhook/polling), ревижн данных, диагностика webhook, тест-пинг |

### Фото

Любое фото, отправленное боту (или пересланное), обрабатывается на лету:

1. если вы стоите в редакторе позиции/афиши/мерча/бранча — фото сразу встаёт туда;
2. иначе бот спросит «куда?» (главная / галерея / бранч / меню / афиша / мерч);
3. скачивается **максимальный размер**, файл кладётся в `data/media/` и по сети раздаётся
   с `Cache-Control: immutable`, приложение обновляется само.

Подпись к фото (caption) становится описанием/подписью, где это уместно.

### Заявки

Формы на сайте (бронь стола, мерч, анкета в команду) уходят в `POST /api/request`
(защита от спама — rate limit), сохраняются в `data/private.json` и пушатся админам
в бота кнопками «в работу / закрыть / стоп-лист». Если бэкенда нет (чистый Pages),
кнопка уводит в чат бота с предзаполненным текстом заявки.

## Структура

```
index.js                  # точка входа (автодетект bothost)
server/boot.js            # env-автоконфиг, webhook/polling, склейка бот↔сайт
server/http.js            # статика + /api/state + /api/request + SSE + /webhook
server/store.js           # состояние (state.json), приват (private.json), media
server/tg.js              # Bot API на нативном fetch (retry/429)
server/admin/panel.js     # вся админка: экраны, редакторы, фото-пайплайн
seed/data.js              # стартовые данные (транскрипция меню с фото из docs/reference)
public/                   # клиент: index.html, app.css, app.js, config.js, data.json (снапшот)
docs/reference/           # референс-скриншоты (меню, афиша, галерея)
scripts/simulate.js       # оффлайн-тест админ-панели
```

## Про данные

Стартовое меню, винная карта и афиша **распознаны с фотографий** (см. `docs/reference/`) —
цены и состава ради интереса: точность не 100%, поправьте через бота за пару минут.
Это не ломает ничего: всё редактируется прямо в админ-панели.
